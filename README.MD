# FNOS 团队目录映射助手 (fnos-teamdir-utils)

这是一个专门为 **飞牛私有云 (FNOS)** 设计的自动化目录管理工具。它通过 Docker 容器运行，利用 Linux 宿主机的 `bind mount` 技术，实现团队公共目录到用户目录的动态映射。

## 🎯 解决的核心痛点

在使用 FNOS 进行团队协作时，团队文件夹在手机客户端和网页端中的访问路径较长，需要多次点击和跳转，效率较低。

本工具通过底层映射，将团队目录直接以快捷方式的形式“拉”到用户的根目录下，彻底解决上述问题。

## 🚀 核心特性

1. **自动团队目录映射**：遍历 `/vol*/@team` 下的所有文件夹，自动挂载到 `/vol1/{UID}/@团队文件-{文件夹名}`。
   * *💡 为了避免与 FNOS 默认的团队文件夹 SMB 共享功能产生视觉冲突，映射目录刻意添加了 `@` 符号前缀。利用系统的机制，这可以在 SMB 共享中自然隐藏，保持挂载盘的整洁。*
2. **状态自愈与防漂移**：每次启动时校验底层 `inode`。如果发现挂载源发生变更或失效，会自动解绑并重新挂载。
3. **不接管个人目录**：工具只管理 `/vol1/{UID}/@团队文件-*` 映射目录，不会创建或修复 `个人文件` 目录。
4. **安全可控的清理模式**：不与容器启停强制绑定。通过 `CLEAN_MODE=1` 变量独立触发清理任务。清理时强制使用 `rmdir`（仅限空目录删除），绝不触碰用户真实业务数据。

## 🛠️ 快速部署

在飞牛的 Docker 界面中，通过 Compose 新增项目，直接粘贴以下配置并启动即可：

```yaml
services:
  fnos-teamdir-utils:
    image: ghcr.io/sqkkyzx/fnos-teamdir-utils:latest
    container_name: fnos-teamdir-utils
    # 必须：开启特权模式并与宿主机共享 PID 命名空间
    privileged: true
    pid: host
    # 安全加固：彻底切断网络访问，防止特权容器的安全隐患
    network_mode: none
    restart: unless-stopped
    environment:
      # 运行模式：0 为常规挂载守护，1 为执行清理任务
      - CLEAN_MODE=0
```

## 🧹 如何安全卸载/清理映射？

如果你不再需要这些映射目录，**请不要手动去删除文件夹**。你可以通过修改 Compose 变量来让工具自动安全清理：

1. 在飞牛 Docker 界面，编辑该 Compose 项目。
2. 将环境变量修改为 `- CLEAN_MODE=1`，保存并重新构建启动。
3. 查看容器日志，当你看到 `[容器已完成清理任务，请手动结束容器]` 时，说明底层映射点已全部安全拆除。
4. 此时你可以放心地停止并删除该容器。

## 🧠 工作原理

该工具采用 **“容器化封装 + 宿主机穿透执行”** 的架构思路：
* **权限穿透**：容器通过 `privileged: true` 和 `pid: host` 模式运行，拥有操作宿主机内核的权限。
* **空间穿透**：利用 Linux 的 `nsenter` 命令进入宿主机的 Mount Namespace，使得在容器内发出的 `mount --bind` 指令，能够真实地作用于 FNOS 的底层宿主机文件系统。
* **无状态守护**：挂载操作是系统内核级的内存状态，NAS 重启后会失效。本工具配合 Docker 的开机自启（`restart: unless-stopped`），在每次系统重启后自动“重放”挂载逻辑，充当了一个动态的、支持逻辑判断的 `fstab` 替代品。

## ⚠️ 重要说明

* **UID 匹配规则**：本工具默认 `/vol1/` 下以纯数字命名的目录为用户真实目录。
* **权限继承体系**：`bind mount` 映射后的目录权限与源目录完全一致。请确保你的源目录（`@team` 下的项目）已经在 FNOS 后台正确配置了团队成员的读写权限。
* **个人目录不接管**：本工具不会创建 `/vol*/{UID}/个人文件`，也不会修改该目录 ACL。个人目录初始化请通过 FNOS 官方界面完成。
